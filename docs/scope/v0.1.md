# v0.1 scope: internet exposure with citations

## Goal

Point Archdiscov at a folder of saved AWS API responses and get, for each EC2 instance and
RDS database, one of three verdicts: `exposed`, `not exposed`, or `unknown`. Each verdict
cites the exact response fields it was decided from. It runs offline against a bundled demo
of a fictional company, Acme, in under two minutes from a fresh clone.

```sh
uv tool install git+https://github.com/TheCthulhuKid/archdiscov
archdiscov exposure demo/acme
```

## Key idea: the raw responses are the evidence

A snapshot is a folder of unmodified AWS API responses (exactly what
`aws ec2 describe-security-groups --output json` prints), plus a manifest. A citation is a
file plus a JSON Pointer into it, such as
`ec2/describe-security-groups.json#/SecurityGroups/2/IpPermissions/0`. The citation can be
checked by opening the file, and v0.2's collector only has to write the same files.

```text
demo/acme/
  manifest.json
  ec2/describe-instances.json
  ec2/describe-subnets.json
  ec2/describe-route-tables.json
  ec2/describe-internet-gateways.json
  ec2/describe-network-acls.json
  ec2/describe-security-groups.json
  rds/describe-db-instances.json
```

```json
{
  "name": "Acme",
  "account_id": "111122223333",
  "region": "eu-west-2",
  "captured_at": "2026-11-01T09:00:00Z",
  "operations": {
    "ec2:DescribeInstances": {"status": "ok", "file": "ec2/describe-instances.json"},
    "ec2:DescribeNetworkAcls": {"status": "denied"}
  }
}
```

An operation that is `denied`, `failed`, or missing from the manifest is **not recorded**. Any
element that needs it is `unknown`, never treated as "nothing there".

`name` is optional and only labels the report. Without it, the header starts with the account
ID.

## Models

These are small Pydantic models built from the responses. Each field a decision reads is a
`Cited[T]`: the value plus its citation.

| Model | From | Fields used |
| --- | --- | --- |
| `Subnet` | `Subnets[]` | id, VPC, IPv4 CIDR |
| `RouteTable` | `RouteTables[]` | VPC, associated subnets, main flag, routes (destination, target, state) |
| `InternetGateway` | `InternetGateways[]` | attached VPCs and attachment state |
| `NetworkAcl` | `NetworkAcls[]` | associated subnets, entries (number, egress, protocol, action, CIDR, ports) |
| `SecurityGroup` | `SecurityGroups[]` | ingress rules (protocol, ports, IPv4 ranges) |
| `Instance` | `Reservations[].Instances[]` | id, Name tag, subnet, public IPv4, security groups |
| `Database` | `DBInstances[]` | id, `PubliclyAccessible`, endpoint port, subnet group subnets, security groups |

Everything else in the responses is ignored. A field that is absent or malformed leaves that
fact unrecorded, and the check reports it as `unknown`.

## The check

Each finding is one resource and one port range. Its **elements** are evaluated in order, and
each element decides `allow`, `deny`, or `unknown` with citations:

| Element | Allow when | Deny when |
| --- | --- | --- |
| `public_address` | the instance has a public IPv4 address, or the database has `PubliclyAccessible: true` | it has none, or it is `false` |
| `route` | the subnet's route table (explicit association, else the main table) has an active route covering the probe address, longest prefix wins, to an internet gateway attached to the VPC | no route, a blackhole, or another target |
| `nacl_inbound` | the lowest-numbered matching inbound entry allows the port range from the probe address | it denies |
| `nacl_return` | the lowest-numbered matching outbound entry allows the return port to the probe address | it denies |
| `security_group` | an ingress rule opens the port range to `0.0.0.0/0` | no group opens it |

**Verdict:** any `deny` gives `not exposed`, because one cited denial is proof enough. If
nothing denies, any `unknown` gives `unknown`. Only when every element allows is the verdict
`exposed`.

**Fixed assumptions** (each one is written up in decision record 0003):
- "Internet" means any address. The probe address is `203.0.113.10` (TEST-NET-3), and only
  `0.0.0.0/0` rules count as open to the internet.
- The return path is checked on one ephemeral port, 49152.
- Port ranges come from the security-group rules open to `0.0.0.0/0` on the resource (tcp,
  udp, or all traffic). A database is checked only on its endpoint port. A resource with no
  open rule gets one `not exposed` finding citing its groups.
- If the first NACL entry that overlaps a port range covers only part of it, that element is
  `unknown`.
- A database whose subnet group mixes subnets that decide the route differently is `unknown`,
  because AWS does not record which subnet hosts it.

**Not evaluated, and listed under every report:** IPv6, load balancers, prefix lists,
security-group references, NAT, peering and transit gateways, ICMP, and host firewalls. Rules
of those kinds never make a resource `exposed`.

NOT EXPOSED  db-billing    tcp 5432   not publicly accessible
NOT EXPOSED  i-worker      -          no public IPv4 address

$ archdiscov exposure demo/acme --explain db-orders

                         ec2/describe-route-tables.json#/RouteTables/1/Routes/1

`--json` prints the same findings as JSON, which v0.3's AI tools will reuse.

## Demo: Acme

One VPC (`10.0.0.0/16`) with an internet gateway, and these subnets:
- `subnet-public-a` and `subnet-public-b`: route table `rtb-public` routes `0.0.0.0/0` to
  the internet gateway.
- `subnet-private-a` and `subnet-private-b`: the main route table, with a local route only.

`-a` subnets are in `eu-west-2a` and `-b` subnets in `eu-west-2b`. There are two subnets of
each kind because every RDS subnet group must cover at least two Availability Zones.

| Resource | Setup | Expected |
| --- | --- | --- |
| `i-web` | public IP, 443 open to the world | exposed tcp 443 |
| `i-bastion` | public IP, 22 open to the world | exposed tcp 22: the finding someone should act on |
| `i-legacy` | public IP, 3389 open to the world, but the NACL on `subnet-public-b` denies 3389 | not exposed, citing the NACL entry |
| `i-worker` | private subnet, no public IP | not exposed |
| `db-orders` | publicly accessible, both public subnets, 5432 open to the world | exposed: the headline |
| `db-analytics` | publicly accessible, `subnet-public-a` plus `subnet-private-b` | unknown, and says why |
| `db-billing` | not publicly accessible, both private subnets, 5432 open to the world | not exposed |

Write the responses by hand, but give them the exact shape the AWS CLI prints. If you can,
compare one file against real CLI output from your own account.

## Code layout and budget

About 1,000–1,500 lines of source.

```text
src/archdiscov/
  evidence.py    Cited[T], Citation, JSON Pointer resolution
  snapshot.py    manifest, coverage, response loading
  models.py      the models above
  normalize.py   responses -> models with citations
  exposure.py    elements, verdicts, findings
  cli.py         exposure and show (Typer)
```

## Tests

Aim for about 20, all offline:
- Resolving a citation, and normalizing one response of each type with its citations.
- One allow and one deny case per element, plus the NACL partial-range case and the
  mixed-subnet database case.
- A not-recorded operation makes its element `unknown`.
- One golden test that runs the whole demo and compares the findings JSON.
- One CLI smoke test of `exposure` and `show`.

## Done when

- `archdiscov exposure demo/acme` prints the table above from a fresh install.
- Every citation in `--explain` opens with `show` and holds the fact it claims.

- The README explains what was checked, what wasn't, and how AI was used.

## Not in v0.1

Collecting from AWS (v0.2), more than one account or region, the AI layer (v0.3), Terraform
(v0.4), MCP (v0.5), and anything in the "Not evaluated" list.
